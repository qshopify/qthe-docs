QThe fires browser events at the moments custom code usually cares about. They're dispatched on `document` as standard `CustomEvent`s, so analytics tags, app embeds and your own scripts can listen without touching theme files. Event names are a stable public API.

```js
document.addEventListener('cart:updated', (event) => {
  console.log(event.detail); // { source, items, cart }
});
```

## Events

| Event | Fires when | `detail` |
| --- | --- | --- |
| `cart:request` | A cart change starts, before the server responds | `type` (add or change), `items`, `key`, `quantity` |
| `cart:updated` | A cart change succeeds | `source`, `items`, `cart` |
| `cart:show` | The cart drawer is about to open after an add | `source` |
| `cart:error` | A cart change fails (sold out, server or network error) | `message`, `source` |
| `cart:unavailable` | The shopper can't add yet — no valid variant selected | `reason`, `sectionId`, `source` |
| `variant:change` | The variant picker resolves a selection | `variant` (empty when incomplete), `sectionId` |
| `drawer:open` | Any drawer or dialog opens — cart, quick view, menu | `id` |
| `drawer:close` | Any drawer or dialog closes | `id` |
| `search:submit` | A search form is submitted | `query` |
| `search:results` | Predictive search shows new suggestions | `query`, `count` |
| `newsletter:submit` | A newsletter form posts back | `success` |
| `section:render` | A section re-renders after a variant change, filter or sort | `attr`, `regions` |

## Example — track adds to cart

```html
<script>
  document.addEventListener('cart:updated', (event) => {
    if (event.detail.source !== 'add') return;
    for (const item of event.detail.items ?? []) {
      console.log('Added', item.id, item.quantity);
    }
  });
</script>
```

Add scripts like this with a **Custom liquid** section, or through your app's app embed — not by editing theme files. See [Custom code](/docs/advanced/custom-code).
